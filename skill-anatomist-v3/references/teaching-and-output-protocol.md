# 技能解剖教授 v3：教学与输出协议

## 1. 把三条流程分开讲

### 用户使用流程

```text
我的问题 → 我怎么开口 → 我提供什么 → 是否需要选择 → 我收到什么 → 我怎么使用结果
```

### 结果形成过程

解释规定的方法为什么能产生预期结果：

```text
先做 X → 产生 Y → 再用 Z 整理或检查 → 所以最终得到 W
```

### 内部实现过程

说明每一步由哪个文件、函数、工具或命令完成。这部分属于可选的深入内容，必须放在最后。绝不能用内部实现过程代替用户使用流程。

## 2. 初学者执行摘要

进入内部细节之前，先用日常中文回答：

- 用一句大白话说，它是什么？
- 它解决了什么真实问题？
- 三种有代表性的适用场景是什么？
- 两三种看起来接近、实际并不适用的场景是什么？
- 用户可以怎么开口？
- 用户必须提供什么？
- 用户最终会收到什么？
- 最值得学习的地方是什么？
- 哪些地方不应照搬或依赖？
- 最终建议是什么：直接使用、选择性研究、只学习某些部分、当作反面教材，还是证据不足？必须给出直白理由，不要给等级。

初学者即使只读到这里，也必须能够理解这个技能对自己的实际意义。

## 3. 术语翻译阶梯

1. 不使用术语，先描述它是什么。
2. 给出一个熟悉的生活类比。
3. 解释它在这里具体做什么。
4. 解释它会怎样影响用户。
5. 最后在可选的深入内容中揭示并定义准确术语。

示例：

- CLI（命令行界面）→ 不是点按钮，而是通过文字命令给程序下口令的入口。
- schema（结构规范）→ 规定数据必须有哪些格子、每格装什么的一张表格模板。
- assertion（断言）→ 用来判断结果是否达标的一道检查题。
- environment variable（环境变量）→ 程序启动前从环境里读取的一张便签。
- local HTTP server（本地网页服务）→ 临时在本机开一个网页入口，让浏览器读取或提交内容。

## 4. 有洞察的教授批注

“这句很重要”“设计很巧妙”或者只是换句话复述原文，都属于无效批注，必须重写。

对于影响较大的段落，至少回答下面一个有证据支持的问题。

### 为什么选择 A，而不是看起来可行的 B？

指出一个可信的替代方案及其好处。解释真实取舍，以及为什么在当前限制下选择 A。要教会读者怎样做选择，而不是宣称“A 永远更好”。

### 这条设计阻止了哪一种偷懒路径？

明确指出模型默认容易犯的具体错误，例如跳过验证、提出不必要的问题、输出空泛内容、不加区分地加载全部材料、把关键决定藏起来，或其他有证据支持的错误。解释这条规则怎样阻断该错误。

### 它把哪个模糊目标变成了哪些可控动作？

例如，把 `结果要专业` 改写为 `生成后渲染，并检查溢出、遮挡和缺页`。把这种转换教成一种可以迁移的方法。

### 哪些内容没有说，或者被有意留白？

找出有价值的判断空间、明确例外、遗漏的失败情形或隐含的平台前提。必须区分“有意留白”和“设计遗漏”；证据不足时直接标为未知。

标准批注结构为：`忠实翻译`、`小白解释`、`教授批注`，必要时增加 `为什么这样而不是那样`，最后给出 `学走 / 别照搬`。

不要为了显得有洞察而虚构替代方案或批评。只有当某个弱点会影响正确使用，或者能够教会读者一条可迁移原则时，才需要指出它。

## 5. 完整原文课堂

按照原始顺序呈现目标 `SKILL.md` 中所有有实际意义的内容，包括前置元数据、标题、段落、列表、示例和代码块。依次编号为 `S001`、`S002`……，并维护下面这份覆盖台账：

```text
原文范围 → 对应片段编号 → 是否已呈现 → 未呈现时的原因
```

每个片段必须包含完整原文、忠实中文翻译、小白解释、教授批注、学走或别照搬的建议，并在需要时解释术语。

设有实际意义的片段总数为 `N`，以下四个数量必须完全相等：

```text
覆盖台账中的片段数
= dossier 中的 total_segments
= dossier 片段数组的长度
= HTML 中实际嵌入的片段数
```

讲得深入不能成为遗漏原文的理由。连接性文字可以简洁批注，影响重大的设计决定则应深入解释。

如果由于访问权限、版权或其他限制无法完整转载，必须明确称为 `选段精读`，说明原因，绝不能让读者误以为已经覆盖全文。

## 6. HTML 教材

只有在教学底稿和结构化档案都已经冻结之后，才能读取并执行本节。

页面顺序必须是：执行摘要；怎样使用；结果为什么会形成；内部解剖；设计启示；照搬风险；完整或选段原文课堂；迁移练习；安静的附录。

不要把评级、硬性封顶、风险雷达或评审方法做成主要导航。

首屏必须直接展示：大白话解释、适用与不适用场景、示例说法、输入与输出、值得学习的地方、注意事项和使用建议。可以在后面增加一句容易记住的核心观点，但不能用它取代清楚说明。

使用流程图必须采用第一人称步骤，并可以区分 `你会看到` 与可选的 `你看不到，但按设计会做`。

原文课堂的版式要求：

- 宽屏上，原文与译文左右并排，中间有清楚但不过度装饰的语义分隔。
- 教学批注放在下方，或用其他方式与原文、译文明显区分。
- 移动端依次堆叠原文、译文和批注。
- 原文和译文始终可见；更深入的批注可以折叠。
- 显示类似 `12/48` 的阅读进度，并提供搜索，但不能隐藏尚未阅读的片段。

桌面端的学习正文和译文通常不得小于 17 像素；批注不得小于 16 像素；标签可以使用 12–13 像素。中文正文不要使用等宽字体。

选择一个有记忆点的教学机制，优先使用“带批注的原文”或“学习主线”。只有真实顺序才使用编号，只有真实差异才使用分栏。避免仪表盘、指标卡片、严重程度颜色、没有必要的渐变、错峰入场动画和悬停缩放。

HTML 必须是一个可以离线打开的独立文件：内嵌 CSS 与 JavaScript，不使用外部字体、内容分发网络、远程图片、分析统计或网络请求。支持“减少动态效果”偏好，使用语义化标题、清楚的键盘焦点、足够的对比度、响应式布局和安全转义。

明确拒绝以下做法：在理解内容前给出 A/B/C 等级；以审计式的好坏判断组织全文；承诺全文精读却自行减少段落；为了模仿目标技能的外观而破坏教学系统。

## 7. 自主完成检查

产物必须沿着一个方向生成：

```text
完整阅读与证据 → 冻结教学底稿 → 结构化档案 → 从档案生成 HTML
```

必须依次通过以下检查：

1. 可用性检查：已阅读所选技能说明、必需参考文件、目标原文和必要的辅助材料。
2. 初学者教学检查：执行摘要能够独立理解；用户流程真实；术语已经翻译；判断以学习为目的。
3. 原文覆盖检查：覆盖台账、结构化档案总数、片段数组长度和 HTML 片段数完全相等；所有必填字段都不为空。
4. 一致性检查：所有产物对使用建议、使用步骤、原文模式与数量、学习重点和注意事项的表达一致。
5. HTML 完整性检查：可以离线使用；内嵌数据能够解析；所有单元都能渲染；导航以学习者为先；转义安全；键盘、移动端和对比度检查通过。

视觉检查只能补充确定性检查，不能取代它们。

状态定义：

- `complete`（已完成）：所有检查均已通过。
- `created, unverified`（已创建但未验证）：文件已经写入，但无法完成必要的回读或检查。
- `incomplete`（未完成）：存在已知的不一致、内容缺失或检查失败。

仅仅成功写入文件，不能宣称任务完成。不要要求上级智能体临时补充指令、索要缺失章节、修复 HTML、对齐数量或代为收尾。

有效评测必须由一个没有受到上级干预的全新智能体完成。如果发生干预，应把该次运行标记为“已受干扰”，不把它计入有效证据；另行修订技能后重新开始。

最终报告必须准确说明：原文采用全文还是选段模式、片段总数、用户流程步骤数、HTML 实际嵌入数量、每项完成检查的结果、视觉检查结果，以及环境限制。
