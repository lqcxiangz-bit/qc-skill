# 页面长什么样

这份文件是**配置项**——照做即可，不用琢磨。唯一要动脑的是第 0 节和第 1 节。

两个模板：`assets/brief.html`（第一问 + 第二问，短）、`assets/scroll.html`（第四问，长卷）。**从模板改，不要从零搭。**

---

## 0. 图怎么画（第一问的命门）

第一问是**图主文辅**——图是主角，字是配角。所以图糊了，整层就废了。

**硬约束：**

- **图上的字 ≤ 30 个。** 超了说明那不是图，是塞了文章的框框。
- **必须有一处标注**，指向「这里本来可以是别的做法」。
- 用**内嵌 SVG**，墨线手绘感：纸色底、墨褐线条、朱砂只用来标那一处。
- **不要画成工程流程图**（一排等宽方框加箭头）——那种图跟这套页面的气质打架，而且它其实什么都没说。

**要画「它少了一步」，必须给出参照物。** 空白单独画不出来——画一个虚线圈、给它起名叫「空」，读者只会看到三个节点排一行，把中间那个当成一个什么都不做的环节。**用多画一个东西来表示这里什么都没有，是自相矛盾的。**

正确的做法是并排对比，让空白被衬出来：

```
别的 skill    话题 ──→ 先核实 ──→ 写稿 ──→ 出图
eli5          话题 ─────────────────────→ 出图
                        ↑ 同样长的距离，中间什么都没有
```

两行等宽，下面那行的空白靠上面那行衬出来。不用给空白起名字，它自己就跳出来了。

### 验收：这一条你自己做不了

「遮住文字只看图，能不能说出它怎么运作」——**作者自己给自己做这个测试永远会通过，因为他已经知道答案了。**

所以：**图的验收必须找一个不知道的人。** 另起一个干净上下文的 agent（或者真人），只给他看图、不给看原文，让他说这图什么意思。**说不出来、或者说岔了，就重画。**

这不是走过场。一张自己觉得很清楚的图被外人一句话测穿，是常有的事。

**画不出来就说画不出来。** 画不出那处「本来可以是别的做法」，通常说明还没读懂原文，回去再读一遍，别硬凑一张方框图交差。

> 反面例子：把「读原文 → 写文字稿 → 生成网页」画成三个一样大的方框排一行、中间箭头连起来。这张图等于没画——它没告诉你**为什么不能倒过来**，而那才是这个流程唯一的判断。

## 1. 一卷不散（长卷最容易翻车的地方）

**会出什么事**：逐段翻译批注的时候，很容易把每一段做成一个**带边框、带底色、带阴影的卡片**。明明是同一份 skill，被样式一切，读起来支离破碎，像一堆互不相干的幻灯片。

**为什么会这样**：每段一个卡片 → 每段成孤岛；段间留白太大 → 断开；章节标题做成整行大横幅 → 把流打断。

**怎么办**（模板里已经做好了，改内容时别破坏）：

- **不给每段做卡片。** 整个第四问共用同一张纸：同一个背景色，没有边框、没有阴影、没有每段单独的底色。
- **段与段只用一条极细的线分开**，加页边一个小段号。分隔要「有，但不吵」。
- **一条从头拉到尾的竖线**，把所有段缝成同一卷，中间不断。这是这套页面最认得出来的记号。
- **段号是挂在那条竖线上的小圆点**：重点段实心，一般段空心，形成一条能快速扫的节奏线。
- 章节标题**轻量化**：页边一个中文序数 + 一行小标题，不做整行横幅。
- **所有段落同一个栏宽、同一个行高**，读起来是一份文档的呼吸，不是一屏一个样。
- 收起来的时候保持紧凑，让原文顺畅往下流；**展开批注是全页唯一被编排的动作**。

一句话：**分隔靠节奏（细线 + 段号 + 竖线），不靠盒子。**

> **三问之间也不许用盒子分隔。** 第一问和第二问在同一张纸上，靠一个更重的章节标题分开，那条竖线照样不断。

---

## 2. 开头是一句判断，不是一句介绍

页面顶上那句话要**表态、能被反驳**。

- ❌ 「本文将拆解 XX 这个 skill」——安全，但没味道
- ✅ 「这不是一个工具，是一段被悄悄塞进模型脑子里的人设」——它断言了一件事

不要用「分析 / 拆解 / 解读」这种中性词起头。

---

## 3. 不要暗色（明确偏好）

- 背景纸色 `#f6f2e9`（偏冷的暖纸，避开 AI 最爱的那种奶油色 `#F4F1EA`）
- 文字墨褐 `#2a2620`，不用纯黑
- 点缀：朱砂 `#c0392b` / 深金 `#8a6d2f` / 苔绿 `#3a6b5b`
- **全页不许有黑块、近黑背景、深色「终端」样的卡片。** 讲运行过程的那几步也用纸色卡片。

## 4. 字要够大

| 哪里 | 多大 |
|---|---|
| 正文 / 译文 | **17px** |
| 原文栏（不论中英） | **17px 正体墨色**。拆英文 skill 时原文栏就是英文，这是设计如此，不是漏译 |
| 批注正文 | **16px**，用衬线体，**不要用等宽**（等宽排中文别扭） |
| 眉标 / 标签 / 段号 | 12–13px（等宽合理） |
| 代码 / 配置块 | 15.5px 等宽，底色略沉 |
| 手机上 | 正文 16px、批注 15.5px |

其他：

- **代码块要换行显示**（`white-space: pre-wrap`），**不要横向滚动条**——横着滚的东西读者经常整块漏看。
- 代码块右边那栏仍然是**说人话的翻译**（这段配置在干什么、哪个字段管什么），不是干巴巴一句「说明」。
- **`**加粗**`、反引号这类标记要变成真正的加粗和代码样式**，不能让符号本身裸露在页面上。（`render.py` 会自动处理，也会检查。）
- **「点击展开批注」要做得显眼**：朱砂描边的药丸按钮 + 14px 粗体，一眼看出能点。别做成不起眼的小灰字。
- **往下一层的入口，做成实心按钮，不是一行小字链接。** 从「靠不靠谱」进「逐段拆解」是全页最重要的一个动作，做成一行带箭头的小字，读者根本看不见它是个入口。朱砂实心药丸 + 16px 粗体。
- **文案说清楚点进去看到什么，别用内部编号。** 「接着看第四问：逐段拆 →」里的「第四问」是这份文档自己的编号，读者不关心；写「接着看 skill 内容的逐段拆解」。
- **相邻的两个块之间要有呼吸。** 结论框和依据框贴在一起会糊成一坨，看不出是两件事——上下各留 30px 左右。

## 5. 结构本身要有意思

编号、眉标、分隔线这些东西要**编码内容**，不是装饰。

- 章节用 序 / 一 / 二 / 三 中文序数——它们确实是顺序，可以。
- **并列的点不要编号。** 几个并排的要点用圆点或标签，别套 01 / 02 / 03——那是 AI 最爱的假结构。

## 6. 动效只用一次

- 批注展开用高度过渡（约 0.4 秒）就够，目的明确。
- **不要**那些散落的淡入上浮、依次入场、鼠标悬停放大——它们只会强化「这是 AI 生成的」感觉。
- **一个被编排过的瞬间，比一堆散落的效果有力得多。**

## 7. 把胆量花在一个地方

现在 AI 生成的页面默认聚在三种长相：暖奶油 + 高对比衬线 + 赤陶点缀；近黑背景 + 一种荧光色；大报纸样式 + 细线 + 零圆角密集分栏。

这套页面**踩在第一种的边上**。所以它的辨识度**不能押在配色上，要押在结构上**：

- 那条从头拉到尾、把所有段缝成一卷的竖线
- 左原文右翻译 + 点开才看得到的批注这个机制
- 批注前面那个小圆章、段号的小节点

**记号集中在这几处，其余安静。** 别再同时把渐变、复杂动效、花哨编号都铺上去。

**全篇最要紧的那一两段**可以标出来（节点做成朱砂实心 + 眉标「先看这条」+ 批注默认展开）。**最多两段，多了等于没标。** 注意它的节点仍然挂在同一条竖线上——轻重靠节点表达，不靠给它套个盒子。

## 8. 明确不做

- 打分、评级、打星
- 通篇按好坏组织，像审稿
- 说好要全文覆盖却自己偷偷减段（做不到就明说是「选段」）
- 为了模仿目标 skill 的长相，破坏这套排版
- 单文件之外的任何外部请求（远程字体、CDN、远程图片、统计脚本）
