# 批注写法：让洞察锋利、让小白能懂

批注是这个 skill 的核心价值。它要同时做到两件事：**对初学者讲得通**（术语翻译阶梯），**又挖到设计的精髓**（回答「为什么这么选」）。一条批注如果删掉后只剩「这句很重要 / 很巧妙 / 体现了深刻理解」，那就是水的，删掉等于没写，重写。

---

## 一、术语翻译阶梯（让小白能懂）

初学者卡住通常不是因为逻辑难，而是因为**黑话**。每遇到一个术语或行业默认，按这五级往下讲，讲到第四级小白就懂了，第五级只是给想深入的人：

1. **不用术语，先说它是什么。**
2. **给一个熟悉的生活类比。**
3. **说它在这里具体做什么。**
4. **说它会怎样影响用户。**
5.（可选）**最后才揭示并定义准确术语。**

示例：

- **CLI**（命令行界面）→ 不是点按钮，而是用文字命令给程序下口令的入口。
- **schema**（结构规范）→ 规定数据必须有哪些格子、每格装什么的一张表格模板。
- **assertion**（断言）→ 判断结果是否达标的一道检查题。
- **environment variable**（环境变量）→ 程序启动前从环境里读的一张便签。
- **被动注入 / injected persona** → skill 不是你手动调用的按钮，而是对话开始时被悄悄塞进模型脑子里的一套人设和规矩，你没看见但它在起作用。

**五级是你脑子里的思考过程，不是页面上的五行。** 落到页面时压成一行——模板 `.ladder` 块写成：`黑话 → 生活类比 → 在这里做什么 → 对你的影响`（第 5 级「准确术语」通常就是开头那个黑话本身，或并进括号）。不要把五级原样铺成一大段塞进单行 div，那会又长又乱。想讲深，就在阶梯下面另起一句正文，而不是把阶梯撑长。

---

## 二、每条批注的结构

1. **小标签（ntag）**：一句话点明这条批注在回答哪个「为什么」。写成具体问题或断言，不要写成分类。
   - ✅「为什么是"小工作室主理人"而不是"大厂设计总监"」
   - ✅「为什么"不准编号"是整篇最反 AI 的一条」
   - ❌「关于配色」「关于字体」——那不构成洞察。
2. **正文 1–3 段**：回答思想层面的取舍，每段要有因果，不要并列罗列。
3. **（关键段）术语阶梯**：把这段涉及的黑话讲给小白。
4. **（关键段）学走 / 别照搬**：学走可迁移的思路；别照搬有前提、换场景会塌的做法。
   - **判据（拿它区分，别靠感觉）**：问一句「**这个坑是『这类问题』的，还是『这个工具 / 这个版本』的？**」
     - 这类问题的通用坑 → **学走**（换到别的 skill 也成立）。
     - 这个工具、这个版本的特定坑 → **别照搬**（版本特定的禁令明年就没了，照抄等于学噪音）。

连接性、过渡性的段落**只写一句简批**（点明它在结构里承担什么职责），不必上全套——把深度留给关键段。

## 三、锋利的五种问法（每个关键段至少命中一种）

### A. 为什么是 A，而不是看着更合理的 B？
指出一个看似更自然、更常见的替代选择，再解释原文为什么偏偏不选它。
> 例：为什么用"小工作室主理人"而不是"大厂设计总监"？因为大厂总监的职业本能是降风险，而降风险正是 AI 的默认失败模式。选 B 等于让模型扮演一个"本能就输出中位数答案"的人。

### B. 它关掉了模型的哪条退路？
原文某句不是在给能力，而是在堵一条模型默认会走的舒适路线。
> 例："不承担风险本身也是一种风险"——把"什么都不做最稳妥"也标成有后果的选择，堵掉"摆烂最安全"这条退路。

### C. 它把哪个不可控目标，变成了哪个可控动作？
很多 skill 给的是模糊目标（"要独特""要专业"），没法验收。锋利的批注指出原文怎么把它落成可控动作。
> 例："有辨识度"是模糊目标，"交出一个 signature"是可检查产物——要么有要么没有。
> 例："独特"被重新定义成"对主题的研究深度"，让模型有事可做，而不是等一个不存在的缪斯。

### D. 它在哪里留了口子 / 沉默在哪？
规则之外的例外和沉默，往往比规则本身更说明问题。至少有一处指出「它没说什么」。
> 例：它说"大数字+小标签+渐变"是模板答案，但没说"永远别用"，而是"只有真的是最优解才用"——留了口子，但把举证责任压给了模型。

### E. 这里作者为什么"犹豫"、为什么不给死规矩？
禁令是**已经解决**的问题（有人踩过、写死了）；**犹豫是还没解决的问题**——那才是这个领域的真实前沿。原文里凡出现"优先用 A，但某种情况用 B""这两个工具都有这毛病，只是方式不同""视情况而定"这类**没给干净答案**的地方，都值得单拎出来深挖：作者在这里不是没想清楚，是**这个问题本身没有干净解**。指出这一点，比复述任何一条硬规矩都值钱。
> 例：它没有规定"一律用 A"，而是"通常 A、遇到 X 换 B"——这不是作者偷懒，是 A 和 B 的取舍随场景翻转，说明这一步没有能写死的最优解，得靠执行时判断。

## 三点五、禁令与括号：应力集中在哪，最高密度在哪

一份 skill 里份量最重的往往不是"怎么做"，是"**这里会炸**"。批注禁令时，两个动作：

1. **别停在复述禁令。** "不要用 SOLID"本身价值约等于一次查询，记住即可，学不到东西。**禁令是坐标，不是内容**——它标出这个系统的应力集中在哪。批注要**从禁令反推**：这里为什么会出问题？它暴露了这个系统的什么**反直觉**性质（我脑子里的模型和现实在哪不一致）？只复述禁令、再补一句原文已经给过的理由，就是不合格。

2. **把括号解压开。** `不要用 SOLID（会渲染成黑色）`——括号里那半句是**全篇密度最高的一行**，它是一次事故的完整压缩。批注要把它拆回三样：**现象**（发生了什么）、**原因**（系统为什么这样）、**代价**（不避会怎样）。原文只给了压缩包，批注负责解压。（注意：括号不一定长成括号——`only opportunity to capture… isn't persisted` 这类"藏在正文里的理由句"同样是压缩包，照样解压。）

**但先分清哪种禁令值得深挖**——这决定你把批注深度花在哪：

| 禁令类型 | 例 | 怎么处理 |
|---|---|---|
| **带理由 / 反直觉** | `不要用 SOLID（会渲染成黑色）` | **关键段，深挖**：解压括号 + 反推系统性质 |
| **无理由 / 纯配置** | `不要用 /skill-test`（没说为什么） | **配置项，不是知识**：简批一句带过，别硬凑深度。它是这个工具的一条约定，照做即可，学不到可迁移的东西 |
| **工具/版本特定** | `某库某版本的坑` | **别照搬**：点明它绑在什么前提上、明年可能就没了（判据见「学走/别照搬」） |

> 一句话：**你拆的不是别人的流程，是别人的事故史。** 禁令后面的括号，就是那段事故史被压到最小的样子——但**没带括号（没给理由）的禁令，只是一条配置，别在上面浪费批注深度。**

## 四、最后一笔：落到这份拆解页自己（可选）

有些批注可以收一句「这份拆解页自己是怎么执行这条规则的」，让拆解成为示范而非讲解：
> 批注"结构即信息"时收一句：这份页面的 序/壹/贰/叁 是中文序数，因为它们确实是顺序章节——通过了"是不是真实序列"的自检。

只在自然的地方加，不要每条都硬凑。

---

## 五、反面教材（避免这种写法）

- ❌「这条体现了对设计的深刻理解，强调了独特性的重要性。」（复述 + 空话）
- ❌「配色和字体的选择很巧妙，给人专业的感觉。」（形容词堆砌，无信息）
- ❌「作者在这里用了对比手法，增强了表达效果。」（语文课式分析，不触及思想）
- ❌「这里规定不要用 SOLID，因为会渲染成黑色。」（只把原文的禁令和括号复读一遍，等于没批注——禁令是坐标，要从它反推系统的反直觉性质、或归到"哪类问题"）
- ✅「它没说"输出要独特"，它说"先把主体具象化"。因为一旦主体具体了，独特输出是自然结果。这是把不可控目标（独特）转化成可控动作（命名主体）的范例。」

最后一条好在：它点出了原文的真实手法（约束输入而非约束输出），并抽象成一条可迁移的元规则。这就是「精髓」——读者学走的不是这条规则，是造这条规则的思路。
